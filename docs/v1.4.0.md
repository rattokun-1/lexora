# Lexora v1.4.0

## 学習モデルの改善

回答 → 端末キュー → 認証済みRPC → 非公開の仮名化データ → オペレーターによるエクスポート → 独自のロジスティック校正モデル → 未使用学習者で評価 → 承認・適用。

`node scripts/model-admin.cjs export data/reviews.json`、`node scripts/train-model.cjs data/reviews.json data/candidate.json`、評価後に `node scripts/model-admin.cjs activate data/candidate.json` を実行します。service_roleキーは運用端末の環境変数のみで使用します。

最低20人、学習500件・検証100件の翌日以降の想起／スペル履歴を要求します。検証のlog lossがFSRSより1%以上良く、Brier scoreが悪化しない場合のみ候補にできます。これは最低限の評価ゲートであり、統計的有意差の保証ではありません。学習者単位で検証データを分離します。選択問題や対戦成績は校正学習から除外します。

独自モデルはFSRSの予測を校正して目標保持率に対応する間隔を選びます。現時点で学習済みのLexora独自係数はなく、初期状態はFSRSです。ロールバックは `node scripts/model-admin.cjs rollback`。既存の予定を一括変更せず次の回答から適用します。

## 収集と保存

氏名・メール・写真をイベントに含めません。識別子との対応表は非公開スキーマに置き、一般ユーザーへのエクスポートを拒否します。必須収集と用途はホームおよび privacy.html で説明します。Supabaseで公開RPCのバッチ・フィールド・認証を検証します。未送信キューは端末に最大500件、サーバー履歴は365日です。オフラインや上限超過によるデータ欠落はあり得ます。

## ランダム対戦

DBのトランザクションで近いレベルの2人を組み合わせ、3秒の開始猶予後に60秒。両者で共通の問題順、サーバー採点、重複回答拒否、最低回答間隔を適用します。ブラウザーゲームのため自動回答・複数アカウントを完全には防げません。賞金・ランキングはありません。相手の個人情報は返しません。

## 旅

12レッスン完了で第6エリア「星渡りの高原」を解放。日本時間の季節に応じて植生・地面色と季節の野営地を変更します。季節の活動は通常の学習に接続し、限定アイテムや期間限定の進行条件は設けません。

## リリース条件

全migrationを順番に適用し、CI、DB権限・RPCテスト、二者対戦、認証メール、データ取り込みを確認してからv1.4.0タグを付けます。日次で lexora_purge_reviews / lexora_purge_duels を実行する運用ジョブが必要です。DB未適用のまま本番配信しないでください。
